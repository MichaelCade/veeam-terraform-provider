Architecture Overview

How `terraform-provider-veeam` Works

Seamless integration between Terraform Core and Veeam VBR REST API.

1
Terraform CLI & HCL

Engineers write standard HCL files defining repositories, managed servers, and backup jobs.

  • State tracking & plan validation
  • Resource dependencies (`depends_on`)
2
Go Provider Engine

Built with Terraform Plugin Framework. Handles bearer token authentication, payload mapping, and schema state.

  • Automatic session token renewal
  • Strongly typed schema validation
3
Veeam VBR REST API v12+

Communicates over HTTPS with Veeam Backup & Replication server API endpoints.

  • Inventory discovery APIs
  • Credential vault integration

Repository Infrastructure

Target Repositories & Immutability

Automating ransomware-hardened storage targets as code.

🛡️ Hardened Linux Immutable Repositories

Provision Linux repositories with single-use credentials and immutability flags to guarantee ransomware protection.

  • veeam_repository_linux with immutability period setting
  • SSH credential decoupling for zero-trust security
  • Automatic XFS fast-clone alignment
☁️ Cloud Object Storage & SOBR

Configure Scale-Out Backup Repositories (SOBR) combining local performance tiers with cloud capacity tiers.

  • veeam_repository_s3_compatible (AWS S3, MinIO, Wasabi)
  • veeam_repository_veeam_vault integration
  • veeam_sobr_repository performance & capacity extent rules
File Protection

Unstructured Data & NAS File Share Guard

Managing enterprise SMB & NFS file share backup jobs in HCL.

SMB & NFS Source Registration

Register corporate NAS file shares directly in Veeam Credential & Inventory manager.

resource "veeam_unstructured_data_nfs_share" "nas_nfs" { path = "192.168.1.50:/exports/data" server_id = "managed-server-guid" }
NAS Backup Jobs (`veeam_job_file_share`)

Configure file protection policies, retention schedules, archive tiers, and snapshot frequency.

  • Protects unstructured file shares across storage arrays
  • Archive retention rules for long-term compliance
  • Delta-scan engine integration
Zero-Downtime Migration

Brownfield Adoption via `terraform import`

Adopt existing Veeam infrastructure into code without interrupting backup schedules.

1
Discover GUIDs

Use dynamic data sources or VBR API to list existing resource GUIDs for jobs, repos, and credentials.

2
Execute Import

Run terraform import to link existing VBR objects into the Terraform state file.

terraform import \ 'veeam_job_vmware.sql[0]' \ e8f23a14-89ab-41c2-9011
3
Continuous GitOps

All future modifications, scheduling updates, and target changes happen via reviewable Git pull requests!

DevOps Workflow

GitOps & CI/CD Pipeline Integration

Provision backup policies alongside application workloads in single deployment pipeline.

1. App & VM Spinup

Terraform provisions cloud/on-prem VMs (Proxmox, VMware, AWS).

2. Veeam Protection Binding

`terraform-provider-veeam` automatically attaches new VMs to relevant backup jobs & immutability tiers.

3. Audit & Verification

Complete visibility in Git commit log. Compliance checks run pre-commit.

Live Code Example

Declarative Backup Stack in HCL

Full end-to-end example provisioning server, repo, and backup job.

# 1. Register Proxmox Server resource "veeam_managed_server_proxmox" "pve_cluster" { name = "pve-node-01.lab.local" description = "Managed by Terraform" credentials = "ssh-cred-guid" } # 2. Provision Hardened Linux Immutable Backup Repository resource "veeam_repository_linux" "immutable_repo" { name = "Linux-Immutable-Repo" host_id = "linux-host-guid" path = "/mnt/backup/hardened" make_recent_backups_immutable = true immutability_days = 30 } # 3. Create Proxmox Protection Job targeting Immutable Repo resource "veeam_job_proxmox" "pve_daily_backup" { name = "Proxmox Production Tier-1 Backup" repository_id = veeam_repository_linux.immutable_repo.id server_id = veeam_managed_server_proxmox.pve_cluster.id objects = ["vm-101-sql", "vm-102-web"] }
